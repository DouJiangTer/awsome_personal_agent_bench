Awesome Personal Agent Bench

Which personal-agent capabilities do existing benchmarks actually test?

现有 benchmark 到底测了哪些个人 agent 能力？

We took Meta Muse's personal-assistant capabilities as a baseline, pulled the task lists of 17 agent benchmarks, and coded every task (1,897 in total) against a 23-code capability codebook, keeping the quoted evidence for each label. This page is the entry point to the coverage matrix, the per-cell examples and the review materials.

我们以 Meta Muse 的个人助手能力为基线，拉取了 17 个 agent benchmark 的任务清单，按 23 个能力码对每个任务（共 1,897 个）逐条编码，并保留每个标签的原文证据。本页是覆盖矩阵、逐格示例和复核材料的入口。

Headline findings

主要发现

  • More tasks does not mean more personal-agent tasks. Only 869 of 1,897 tasks (46%) are mainly about the user's own communication, schedule, shopping and travel, or personal data; 494 (26%) touch none of the 23 capabilities.
  • Well covered: email (10 benchmarks with at least 3 tasks), calendar (12), web actions and ordering, preference memory, prompt injection.
  • Thin or outside personal settings: delegated-authority and consent checks (112 tasks, 80 of them from MasDrift's enterprise workflows; 39 in personal settings), self-report honesty (26 tasks, 5 in personal settings), background monitoring (107 tasks, 100 from SentinelBench's synthetic pages), negotiation (135 tasks, all from two game simulations).
  • Combination queries return zero: shopping × authorization or risky actions, negotiation × authorization or honesty, background monitoring × failure reporting. Health/finance data × any safety or privacy code returns 1 task.
  • Two limits of task lists: problems such as a client app reading data the user refused it access to leave no trace in benchmark tasks, and the benchmarks evaluate models inside open-source agent harnesses, not hosted consumer products.
  • 任务多不等于个人 agent 任务多。1,897 个任务里只有 869 个（46%）主体是用户自己的通信、日程、购物出行或个人数据；494 个（26%）不涉及 23 个能力中的任何一个。
  • 覆盖较好：邮件（10 个 benchmark 各有至少 3 个任务）、日历（12 个）、网页操作与下单、偏好记忆、提示注入。
  • 单薄，或不在个人场景：委派授权与同意（112 个任务，其中 80 个来自 MasDrift 的企业流程，个人场景仅 39 个）、自述真实性（26 个，个人场景 5 个）、后台监控（107 个，100 个来自 SentinelBench 的合成网页）、议价（135 个，全部来自两个博弈模拟）。
  • 组合查询命中为 0：购物 × 授权或风险操作、议价 × 授权或诚实、后台监控 × 故障上报。健康/财务数据 × 任一安全或隐私码只命中 1 个任务。
  • 任务清单的两个局限：客户端应用越过用户拒绝的授权去读取数据这类问题，不会在 benchmark 任务里留下痕迹；这些 benchmark 评的是开源 agent 框架里的模型，而不是托管的消费级产品。

How the coding was done

编码是怎么做的

  1. Collect. Task lists were pulled from public repositories, datasets and paper appendices. 11 benchmarks are full lists, 6 are samples.
  2. Codebook. 23 capability codes (messaging, email, calendar, browser, shopping, booking, negotiation, planning, background monitoring, proactivity, memory, health/finance data, tool building, five safety sub-codes, local files, third parties, multimodal, self-report honesty, failure recovery). A label needs the task to require the capability or explicitly grade it, plus a quoted evidence snippet.
  3. Two independent coders (two isolated instances of one language model) labeled every task.
  4. Adjudication. 349 code disagreements and 137 relevance disagreements were resolved by a third instance under written rules.
  5. Cross-checks. Median Cohen's κ across codes is 0.92. A keyword screen independent of the model flags possible misses. Compared with an earlier hand-made matrix, 186 of 285 cells kept their level, 83 went up and 16 went down.
  1. 收集。从公开仓库、数据集和论文附录拉取任务清单。11 个 benchmark 是完整清单，6 个是抽样。
  2. 编码本。23 个能力码（消息、邮件、日历、浏览器、购物、订票订位、议价、规划、后台监控、主动性、记忆、健康/财务数据、自建工具、5 个安全子码、本机文件、第三方、多模态、自述真实性、故障恢复）。打标签要求任务必须做到该能力或评分明确考核，并附原文证据。
  3. 两名独立编码员（同一个语言模型的两个隔离实例）对每个任务标注。
  4. 裁决。349 个码分歧和 137 个相关度分歧，由第三个实例按成文规则裁决。
  5. 交叉检查。各码 Cohen's κ 的中位数为 0.92；另有一个独立于模型的关键词筛查，标出可能漏标的任务。与更早的手工矩阵相比，285 个格子里 186 个等级不变，83 个上调，16 个下调。

Limitations

局限

  • Some task texts are truncated or lack grading details (ClawsBench, OpenClaw Arena, Claw-Eval, π-Bench multi-turn). Coverage there is likely underestimated.
  • PersonalWAB's user histories are not part of the task text, so its memory coverage is underestimated.
  • For sampled benchmarks, "no task found" cannot be extended to the full set.
  • The coding measures whether a kind of task exists and is graded. It does not measure task quality or product-level issues.
  • Only 3 raw entries were spot-checked against the source repositories; the rest were not re-checked one by one.
  • 部分任务文本被截断或缺评分细则（ClawsBench、OpenClaw Arena、Claw-Eval、π-Bench 的多轮部分），这些 benchmark 的覆盖多半被低估。
  • PersonalWAB 的用户历史不在任务文本里，它的记忆覆盖被低估。
  • 抽样 benchmark 里"没找到任务"不能外推到全集。
  • 编码衡量的是"有没有这类任务、评分是否考核"，不衡量任务质量，也不衡量产品级问题。
  • 只随机抽了 3 个原始条目与源仓库比对，其余没有逐条回查。

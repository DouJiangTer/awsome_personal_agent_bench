# 编码本 v2（Codebook）— 根据 WildClawBench 试标校准

目的：判断一个 benchmark 的**每个任务**是否要求、或明确评分考核了某项“个人 agent 能力”。以 Meta Muse 的能力清单为基准，共 19 个能力域，其中安全类 C14 拆为 5 个子码。

## 编码单位与总规则
1. 编码单位是**单个任务/案例**（一行数据），不是整个 benchmark。
2. 可多标（multi-label）。一个标签成立的条件：**完成任务必须做到该能力**，或者**评分标准/预期行为里明确考核该能力**。仅仅是环境里出现相关物件（例如任务背景提到邮件但不要求操作邮件）不算。
3. 依据只能来自任务文本本身（题面、预期行为、评分项、类别名）。**不得凭对 benchmark 名声或作者意图推断**。文本证据不足以判断时，不打标，并在 `uncertain` 里写明原因。
4. 每个标签必须给出**证据片段**（从任务文本中原样摘出，≤30 字）。
5. 同时给出 `relevance`（个人助手相关度）：
   - `core`：任务的主体是用户自己的通信、日程、购物/出行、个人数据、偏好或个人生活事务（如回复邮件、约会议、代购、订票、健康/财务数据）。
   - `adjacent`：通用助理类工作（调研、写文档/做海报、整理文件、办公沟通汇总），个人也会用到，但不是个人生活事务本身。
   - `none`：纯编程、算法/拼图、模型评测工程、论文复现等与个人助手无直接关系的任务。
   - 安全类任务：按其**场景**判定 relevance（例如“帮我改我明天的起床时间文件”为 core，“执行 rm -rf /”为 adjacent）。

## 能力码（code）

| 码 | 名称 | 操作性定义（打标条件） | 不打标的例子 |
|---|---|---|---|
| C1 | 消息/聊天渠道交互 | 任务要求在即时通讯/聊天工具（Slack、WhatsApp、iMessage、群聊、线程）中读取、回复、汇总或路由消息 | 只读本地聊天记录文件而无渠道交互，且不考核对话 |
| C2 | 邮件 | 要求读取、起草、发送、分拣或回复电子邮件 | 仅提到“通知”“消息”但不是邮件 |
| C3 | 日历/日程/提醒 | 要求读取或写入日历、安排会议、处理时间冲突、时区换算、设置提醒或截止日期跟踪 | 仅提及日期作为检索条件 |
| C4 | 浏览器/网页操作 | 要求在网站上点击、填表、导航、登录、提交（含真实或模拟网站），不含单纯的搜索引擎查询或调用 API 抓取 | 用 API 抓取 arXiv |
| C5 | 购物/结账/支付 | 涉及挑选商品并下单、加购、结账、价格比较用于购买、订餐、支付 | 纯商品知识问答 |
| C6 | 出行/订票/订位/活动 | 涉及订机票、酒店、餐厅位、票务、行程变更处理 | 查询景点位置信息但不涉及预订 |
| C7 | 议价/谈判 | 需要与对方就价格、条款进行讨价还价或说服，代表用户立场（含买卖博弈） | 多方协调会议时间（归 C3） |
| C8 | 目标规划/长程个人任务 | 需要把模糊的目标拆成计划并推进（学习计划、健身计划、项目规划、跨会话的多阶段任务） | 单步任务 |
| C9 | 后台运行/监控 | 需要在较长时间内等待外部事件、周期性检查、定时/循环执行，并在条件满足时响应 | 单次长耗时计算 |
| C10 | 主动性 | 需要在用户没有明说的情况下发现隐含需求/隐藏意图并主动处理或提醒 | 按明确指令执行 |
| C11 | 个人记忆/偏好 | 需要记住、使用、更新或遗忘用户偏好/画像/历史信息，跨轮或跨会话 | 单轮内的上下文引用 |
| C12 | 健康/财务/生活数据 | 涉及个人健康、健身、饮食、银行流水、预算、订阅、保险等个人敏感数据的处理或建议 | 机构金融研究、市场分析 |
| C13 | 自建工具/技能 | 需要 agent 自己编写脚本/技能/工具来完成任务，或安装/创建技能 | 只是调用已有工具 |
| C14a | 安全-注入/不可信内容 | 任务中含来自文件、网页、邮件等不可信来源的指令，考核 agent 是否受其操控 | 用户本人的指令 |
| C14b | 安全-凭证/密钥卫生 | 涉及密钥、密码、令牌、个人标识符的暴露风险，考核不泄露/不硬编码/不外传 | 普通登录 |
| C14c | 安全-破坏性/风险操作谨慎 | 涉及删除、覆盖、格式化等不可逆或高风险操作，考核是否谨慎 | 常规写文件 |
| C14d | 授权与同意 | 考核 agent 是否在需要时请示、遵守用户拒绝、不越过授权范围、只起草不发送、遵守权限声明 | 泛泛的“请小心” |
| C14e | 安全-有害/虚假内容拒绝 | 考核是否拒绝生成有害内容或传播虚假信息 | 普通写作 |
| C15 | 本机/系统与文件操作 | 要求操作本地文件系统、命令行、本机应用或系统权限（不含纯读单个附件） | 只在网页里操作 |
| C16 | 第三方/他人隐私与交互 | 任务涉及与非用户的第三方沟通，或考核对第三方/无关个人信息的保护 | 只与用户对话 |
| C17 | 多模态理解 | 需要理解图片、视频或音频内容才能完成 | 仅有截图附带、不需要理解 |
| C18 | 自述真实性 | 考核 agent 对自己所做/所知的说明是否属实，例如不假装完成、证据支撑的完成声明、来源说明 | 只要求输出结果文件 |
| C19 | 稳定性/故障恢复 | 任务注入了故障、扰动、状态变化，考核错误恢复、重试、部分失败汇报、变化后重新核验 | 无故障的常规任务 |


## v2 澄清（试标后新增，优先于上表的模糊之处）
- **C15**：只在任务的**核心**是管理/改动/清理用户本机或工作区里“已有”的文件、目录、应用或系统设置（整理、迁移、批量重命名、删除、改权限、装卸软件）时才标。仅仅“把结果写入 results 目录”“运行脚本完成计算”“解压后读取”**不标**。
- **C13**：仅当任务**明确要求**创建/安装可复用的工具、脚本或技能（skill、插件、自动化脚本）作为交付物，或安全任务涉及 skill 安装时才标。“可以用代码解题”“为了解谜自己写代码”**不标**。
- **C17**：仅当**必须**看/听懂图片、视频、音频的内容才能完成（例如根据视频写笔记、识图分类）。图片只是文件格式/背景、或已给出结构化数据时不标。
- **C19**：只标**故障/扰动注入**（服务报错、超时、部分失败、被撤销/变更后必须重新核验、邮件/消息改动了先前信息且任务要求处理这种变化）。普通“信息冲突需要核对”不标。
- **C18**：仅当评分/预期明确考核“不谎报完成、如实汇报、给出来源/证据、承认无法完成”时才标。
- **C10**：仅当文本明确说存在“隐含/未明说的需求”，或评分要求发现题面没点名的事项时才标。
- **C14a**：标准 = 任务里有一条**试图指挥 agent 的指令**，来自文件/网页/邮件/技能/评论等非用户来源，且评分考核 agent 是否服从。普通的外部邮件内容、演练消息本身不算，除非明确设为诱饵/需要辨别。
- **C14c / C14d**：任务给出固定约束（如“不要修改原文件”）本身不足以标；需要**评分/预期明确检查**agent 是否违反（C14c＝不可逆/高风险操作；C14d＝请示、拒绝、只起草不发、权限范围）。
- **C16**：需要与用户以外的人沟通/代表用户对第三方行动，或明确考核对无关第三方信息的保护。仅仅“汇总同事的聊天”不标，除非要求回复/转发/通知他人或考核隐私边界。
- **relevance 补充**：办公群聊/收件箱里的沟通任务（Slack/邮件/会议协调）算 `core`（个人沟通事务）；纯技术工作流、论文/仓库/数据处理、模型评测、拼图/算法任务算 `adjacent` 或 `none`（前者为通用助理办公，后者为编程/评测）。
- **截断文本**：text/expected 被截断时，只基于可见文本；看不全导致拿不准的，写入 uncertain，不打标。

## 覆盖等级（用于矩阵，按“被标注的任务数”）
- ● 明确覆盖：某 benchmark 中该码被标注的任务数 ≥ 3
- ◐ 零星覆盖：1–2 个任务
- ○ 未见：0 个任务（在本次抓取到的任务清单范围内）
同时给出该码在该 benchmark 内占全部任务的比例。

## 输出格式（每个任务一行 JSON）
{"task_id": "...", "relevance": "core|adjacent|none", "codes": ["C2","C3"], "evidence": {"C2": "原文片段", "C3": "原文片段"}, "uncertain": "可空，写明拿不准的点"}

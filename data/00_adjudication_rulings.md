# 裁决规则（由主研究者在看到分歧分布后制定，公开留档）
裁决人对每个分歧项（编码员之一标了、另一个没标；或 relevance 不一致）逐条做决定。总原则：按 codebook.md（v2）的“必须做到或评分明确考核 + 原文证据”判定，证据不足则 exclude。以下为针对反复出现的定义争议的统一裁决：

R1  C16：仅当任务要求 agent 与“用户以外、且不是谈判对手方本身”的人沟通/代表用户行动（例如通知同事、回复客户、转发、发邮件给第三方），或评分明确考核对无关第三方信息的保护/隐私边界时才 include。与买卖对手方就价格/条款谈判本身只算 C7，不算 C16。
R2  C11：仅当任务需要记住/使用/更新已存的用户偏好或画像（跨轮、跨会话、历史记录、用户档案、memory 文件）时 include。偏好只是写在同一条题面里的需求描述（如“I also prefer…”）不算。
R3  C5：仅当涉及为购买而挑选/比价/下单/结账/支付（含买家与卖家就商品成交）时 include。打车、租房等服务议价不算 C5；打车/出行服务的价格协商算 C6 include；长租房协商不算 C5/C6。
R4  C18：仅当评分/预期文本明确考核如实汇报、不谎称完成、承认做不到、不编造、给出来源/证据时 include。题面只是要求“如缺文件先说明”或“汇报结果”不算。
R5  C4：仅当文本明确要求在网页/浏览器里点击、导航、填表、登录、提交，或明确写 browser/website/web page/UI 操作时 include；只通过 API/工具调用模拟服务而未提浏览器/网站的不算。
R6  relevance：core＝主体是用户自己的通信（邮件/聊天/短信）、日程、购物/出行/订位、个人数据（健康/财务/生活）、偏好或个人生活事务；adjacent＝通用助理式办公/调研/文档/数据分析、企业内部业务处理（CRM/HR/运维报表等，邮件或日历仅作为数据来源）；none＝纯编程、算法/拼图、模型评测工程。选与文本最吻合的一项（不限于两位编码员给的选项，但优先在两者之间选）。
R7  其他码：证据不是明确要求或明确评分项 → exclude；原文能直接印证 → include。截断文本只按可见部分判断。
